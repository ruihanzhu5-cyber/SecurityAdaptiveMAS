# v0.3 联合组织算法：当前实现与研究边界

> 状态：本地代码原型，已通过离线夹具测试；尚未运行 v0.3 的 DeepSeek／ARE 完整 episode。本文描述实际代码路径，不把研究假设写成实测结论。

## 研究问题

长任务中，任务需要的信息、可疑内容的位置和模型输入成本会一起变化。只为节省调用而派工，可能把低可信结果送到有写工具的 Agent；只隔离可疑 Worker，又可能让用户任务缺少必要输入。v0.3 在**一次候选决策**中检查这三件事，并把选中的局部修改应用到唯一的运行图 `G_t`。

## 生效图和可见证据

`GraphRuntime` 保存 Agent 实例、任务分配、有向消息路由、已登记结果对象的读取许可和工具能力。`preview` 在当前图版本、观察序号和任务修订号上试算；`apply` 才改变真实路由和访问关系。运行中已到达的 USER／ENV 消息、工具结果、Worker 输出进入 `OnlineObservation` 和 `ProvenanceStore`；未来通知、官方 Oracle、攻击目标 ID 不进入选图器。

`TaskNeed` 从已登记的信息需求派生。状态取 `available`、`producible`、`blocked` 或 `unknown`，依据当前对象和图关系判断；`available` 表示对象可读，**不**表示内容正确或整个用户任务完成。低可信来源沿派生对象保留，改名或摘要不会自动改成可信用户授权。

## 一次决策实际怎样走

```text
已到达事件 / Worker 输出 / 当前模型输入统计
  → FrameworkTeam 在派工前或结果交付前调用 Controller
  → JointTrigger 检查新增任务修订、Worker 输出、风险事件或重复对象输入
  → 生成 KEEP、显式只读派工、RELEASE、CONTAIN 等局部候选
  → 对完全相同且属于同一提供任务的重复输出尝试少交付一份
  → 对已知需求缺口，最多检查 2 项、寻找已存在的独立非可疑结果对象
  → GraphRuntime.preview 验证版本、实例上限、工具能力和对象读取许可
  → 同一候选记录任务覆盖、当前存活对象的结构可达性、可见即时负载
  → 冻结的确定性规则选择；GraphRuntime.apply 改变实际执行关系
  → 消息网关和对象读取检查后交付；后续真实 usage 进入共享预算
```

候选最多 8 个，活动 Agent 最多 3 个。一个明确的只读任务契约就可以启动一个 Worker；两个互相独立的契约可以启动两个，但当前执行仍是**顺序**的。修复候选只复用一个已存在、由另一存活且未被标为可疑的 Worker 产生的对象；当前实现还要求该对象的来源链不含低可信输入。这是狭窄的可执行替代，不是通用重新检索、字段验证或摘要净化。找不到对象时，候选记录 `no_independent_clean_object` 或具体不支持原因；不会删掉 TaskNeed 以让隔离方案看似可行。

没有新任务、输出、风险或重复输入证据时，Controller 记录延后原因并保持当前图；相同的只读契约和图版本也不会反复派工。Worker 交付后的回收属于已开始工作的生命周期收尾。

## 选择规则与成本口径

先排除无法执行或造成**已知**信息需求缺口的候选。`joint`、`reactive_isolation` 和 `task_plus_filter` 再比较已配置受保护写工具的结构可达数量；`task_only` 不用该风险值选图。对可比候选，选更少的**已知即时交付字符数**；若仍无法区分，保持确定性顺序。明确的只读契约允许一次有预算上限的探索。这个实现是**风险优先的启发式选择**，没有校准的未来成本区间，也没有声称找到全局 Pareto 最优或最小净成本。

模型输入日志分开记录请求准备、提交和响应后真实 usage；实际 Token／费用按调用用途汇总。预算预检拒绝只记拒绝，不增加实际请求与 Token。交付对象的字符数以及重复展开的字符数是代理统计，**不是精确 Token 节省**。未来模型调用、重试和完成时间目前是 `unknown`，因此不能据这套估计宣称 v0.3 更便宜。

受保护目标由本轮可用 ARE 工具元数据中可写工具通用生成，排除给用户回复的 AUI 工具；它不读取当前攻击配置。风险投影只覆盖当前登记的对象、读取许可、路由和工具能力，给出潜在路径及见证，不等于模型实际接触恶意文本、发起越权调用或造成环境伤害。ARE 应用侧未建模的共享状态旁路仍是 `risk_scope=incomplete`。

## 对照策略

| 策略 | 同一网关与运行图下的差异 |
|---|---|
| `task_only` | 任务／即时成本候选；风险检测仍记录，但不参与选图。 |
| `task_plus_filter` | 先按任务／成本提出候选，再做风险准入；若被拦，选当前可用的简单扣留／隔离并记录未满足的需求，不主动修复。 |
| `reactive_isolation` | 无风险时照常按任务派工；可疑 Worker 出现后选择简单隔离，并记录因此缺失的需求，不做替代对象搜索。 |
| `joint` | 同一候选表中比较任务、风险和成本，并尝试有界的已存在对象替代。 |

四者不是 MANTA、ATM 或 DynaTrust 的官方复现。旧 `legacy` 选择器保留给原有直接调用的回归测试；CLI 的 v0.3 入口选择上述四种策略。

## 与近邻工作的关系

[MANTA](https://arxiv.org/abs/2607.28527) 已研究运行时有界拓扑修改；[ATM](https://arxiv.org/abs/2607.20488) 已研究过载触发以及能力、状态和影子验证约束；[SAIGE](https://arxiv.org/abs/2609.19759) 研究按需组织；[SafeFlow](https://arxiv.org/abs/2607.25255) 研究恶意语义的信息流控制；[Prudentia](https://arxiv.org/abs/2602.11416) 研究安全策略约束下的规划。本项目尚需证明：外部风险事件触发的局部改图，能否在相同任务质量和工具边界下同时改善传播控制与净成本。当前代码与一组离线夹具不能回答这个问题。
